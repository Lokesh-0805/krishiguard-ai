Abstract

Plant diseases cause large yield losses, and farmers often lack quick access to an expert. KrishiGuard AI is a responsive web application in which a farmer uploads, photographs or pastes an image of a crop leaf and receives the crop, the disease (or healthy), a calibrated confidence, a heat-map explanation and advisory in English and Hindi (symptoms, causes, prevention, organic and chemical options with cited agricultural sources).

An ImageNet-pretrained EfficientNet-B0 convolutional neural network was fine-tuned with transfer learning on the PlantVillage dataset (54,305 images, 38 classes, 14 crops) using a leakage-free, group-level split. On 7,751 held-out test images it reaches 99.56% accuracy, 99.46% macro precision, 99.52% macro recall and 99.49% macro-F1. Testing on two independent real-field datasets (PlantDoc and a tomato field dataset from Pakistan) shows the well-known lab-to-field gap (31.1% and 26.5% accuracy); the system therefore uses temperature scaling and validation-selected thresholds to label results as confident, uncertain or not recognised, and shows treatment advice only for confident results.

The model is served with ONNX Runtime from a FastAPI backend and a Next.js frontend, both deployed free on Vercel. The project includes 44 backend tests, 6 component tests and 16 end-to-end browser tests (desktop and mobile), all passing.

Keywords: plant disease detection, transfer learning, EfficientNet, PlantVillage, calibration, Grad-CAM, ONNX, FastAPI, Next.js, Hindi advisory.

Chapter 1Introduction

1.1 Problem statement

Farmers should be able to photograph a crop leaf and immediately learn whether it is diseased, which disease it is likely to be, how sure the system is, and what preventive and treatment options exist — in a language they understand. The solution must run in any browser (desktop, tablet, phone) without installing an app.

1.2 Objectives

  1. Identify the crop and disease (or healthy state) from a single leaf photo.
  2. Report a confidence score and clearly flag uncertain or unrecognised photos.
  3. Explain the prediction visually with a heat-map.
  4. Provide symptoms, causes, prevention, organic and chemical options in English and Hindi, with sources.
  5. Evaluate honestly on an untouched test set and on independent real-field images.
  6. Deliver a professional, responsive web application with a real performance dashboard.

1.3 Scope

38 classes over 14 crops: apple, blueberry, cherry, corn (maize), grape, orange, peach, bell pepper, potato, raspberry, soybean, squash, strawberry and tomato (26 diseases + 12 healthy classes). The system is a decision-support tool and not a substitute for an agricultural expert.

1.4 Organisation of the report

The following chapters review related work, describe the development environment, the system architecture, the datasets and their preparation, the model and every training experiment performed, calibration, results, explainability, the advisory engine, the web application and API, testing and deployment, and finally the limitations and conclusions.

Chapter 2Literature Review

2.1 Deep learning for plant disease classification

Mohanty, Hughes and Salathé (2016) introduced large-scale deep learning for leaf disease recognition on the PlantVillage dataset (54,306 images, 38 classes) and reported up to 99.35 % accuracy with GoogLeNet trained by transfer learning. They also noted that accuracy fell sharply on images taken under conditions different from the training data — the first documented sign of the lab-to-field gap that is examined again in this project.

2.2 Real-world (field) datasets

Singh et al. (2020) released PlantDoc, a dataset of 2,598 images collected from the internet with natural backgrounds and multiple leaves per image. Models trained only on PlantVillage performed poorly on PlantDoc, which motivated using PlantDoc and an independent tomato field dataset as external test sets in this work.

2.3 Efficient convolutional networks and transfer learning

Transfer learning reuses features learned on ImageNet and fine-tunes them on a smaller target dataset, giving high accuracy with modest data and compute. EfficientNet (Tan and Le, 2019) scales network depth, width and input resolution jointly; its smallest member, EfficientNet-B0 (≈ 5.3 M parameters with the ImageNet head, 4.1 M with a 38-class head), offers a good accuracy–cost trade-off for CPU deployment, which is why it was chosen here.

2.4 Calibration and explainability

Guo et al. (2017) showed that modern neural networks are over-confident and that a single temperature parameter fitted on validation data substantially improves calibration. Selvaraju et al. (2017) proposed Grad-CAM, which produces class-specific heat-maps from gradients of the last convolutional layer; for networks ending in global average pooling it reduces to the Class Activation Map (CAM) of Zhou et al. (2016). Both ideas are used to make the predictions of this system more trustworthy.

2.5 Gap addressed by this project

Many student and research prototypes report only PlantVillage accuracy with random splits. This project adds (1) a leakage-free group split, (2) external field evaluation, (3) calibrated confidence with explicit uncertainty states, (4) visual explanations and (5) a bilingual, source-cited advisory delivered through a deployed web application.

5.3 Class balance

The dataset is strongly imbalanced: the largest class (Orange — Haunglongbing (Citrus greening)) has 5,507 images and the smallest (Potato — healthy) only 152 — a ratio of 36.23×. This is handled with class-weighted loss and macro-averaged metrics.

Chapter 6Data Preprocessing and Leakage-free Splitting

PlantVillage contains several photos of the same physical leaf. A random image-level split would put almost identical photos in both training and test sets and inflate accuracy. Images were therefore grouped by (1) the dataset's own leaf-identity map, (2) exact byte duplicates and (3) perceptual-hash near-duplicates, and whole groups were assigned to train / validation / test (≈ 70/15/15, stratified by class, seed 42). A script assertion guarantees that no group crosses splits.

6.1 Augmentation and normalisation

  • Training: random resized crop to 224 px (scale 0.55–1.0), horizontal and vertical flips, rotation up to 30°, brightness / contrast / saturation jitter, very small hue jitter (leaf colour is diagnostic), occasional Gaussian blur.
  • Evaluation and serving: resize the short side to 256 px, centre-crop 224 px, ImageNet mean/std normalisation. The serving code is unit-tested to produce numerically identical input to the training pipeline.

Chapter 7Model Architecture and Training

7.1 Architecture

EfficientNet-B0 (Tan & Le, 2019) is a compact convolutional network built from mobile inverted-bottleneck (MBConv) blocks with squeeze-and-excitation, scaled for depth/width/resolution. The ImageNet-pretrained backbone (timm) was kept and its classifier replaced by a new 38-class linear layer with dropout 0.2. Parameters: 4.06 M; input 224×224×3; exported model size 16.5 MB.

7.3 Training procedure (step by step)

  1. Load data: each batch of 32 images is read from the split manifest, decoded, augmented (random resized crop, flips, rotation, colour jitter, blur) and normalised; 3 parallel data-loader workers feed the GPU.
  2. Model: EfficientNet-B0 with ImageNet weights; the 1000-class head is replaced by a 38-class linear layer.
  3. Fine-tuning: all layers are trained. The new head uses the base learning rate; the pretrained backbone uses a smaller rate (×0.40) so that ImageNet features are adapted gently.
  4. Loss: cross-entropy with label smoothing (0.12) and per-class weights (inverse square root of class frequency) to counter the 36× class imbalance.
  5. Schedule: learning rate rises linearly for the first 5 % of steps, then follows a cosine decay to zero.
  6. Validation every epoch: accuracy, macro-F1 and weighted-F1 on the PlantVillage validation split and on the PlantDoc external-validation split are logged to MLflow; the checkpoint with the best validation macro-F1 is kept.
  7. Early stopping: training stops if validation macro-F1 does not improve for 2 epochs (here all 5 epochs ran because the score kept improving).

Chapter 8Confidence Calibration and Uncertainty Handling

A softmax score is not a guarantee of correctness. The system therefore:

  1. fits a single temperature T = 1.055 on the validation sets (lab and field weighted equally);
  2. selects a confident threshold τ = 0.730 and a reject threshold τr = 0.647 on validation data only (rule: target unreachable on some domain -> threshold maximising balanced selective accuracy at >=10% coverage);
  3. reports confident (p ≥ τ), uncertain (τr ≤ p < τ, advice hidden, top-3 shown) or not recognised (p < τr);
  4. never reports a blurry photo (variance-of-Laplacian below the 1st validation percentile, 36.99) as confident.

9.3 External (field) evaluation

The drop from lab to field photos (99.6% → 31.1% on PlantDoc and 26.5% on the tomato field set) is the classic dataset-bias result reported by the PlantDoc authors: a model trained only on single leaves photographed on a plain background does not transfer to cluttered field photos.

9.4 Error analysis

  • Internal: errors occur between visually similar lesions on the same crop — e.g. Tomato — Tomato Yellow Leaf Curl Virus → Spider mites Two-spotted spider mite (4); Tomato — Late blight → Early blight (4); Corn — Northern Leaf Blight → Cercospora leaf spot Gray leaf spot (4); Grape — Esca (Black Measles) → Black rot (2).
  • PlantDoc: healthy leaves on the plant are confused with other crops' healthy classes or with blights; crop-level accuracy is only 58.1%.
  • Tomato field: healthy field leaves are called Late or Early blight; Septoria ↔ Early blight and Leaf Mold ↔ Late blight are the main confusions — natural light, shadows and soil look like lesions to a lab-trained model.

Chapter 10Explainability (Grad-CAM / CAM)

Grad-CAM (Selvaraju et al., 2017) highlights the image regions that most influenced the predicted class score. EfficientNet-B0 ends with global average pooling and one linear layer, so Grad-CAM at the last feature map equals the classic Class Activation Map (CAM = classifier weights × feature maps) up to a constant factor. The deployed ONNX model therefore outputs the CAM directly, without gradients. This equivalence was verified numerically: minimum correlation between CAM and Grad-CAM = 1.00000000; ONNX predictions agree with PyTorch on 105 test images (max logit difference 1.0e-05).

Heat-maps show influence on the class score; they are a sanity check, not proof that a diagnosis is correct.

Chapter 11Bilingual Advisory Engine

A structured JSON knowledge base (advisory/diseases.json) holds one entry for each of the 38 classes with crop and disease names, scientific name, pathogen type, summary, symptoms, causes, prevention, organic options and chemical options — every field in English and simple Hindi. It cites 52 distinct sources (ICAR / NIPHM integrated pest management packages, TNAU Agritech, Kerala Agricultural University, National Horticulture Board, FAO and university extension services), each fetched and dated.

  • No dosages are ever given; chemical options are listed only as "options reported by <source>" and every list ends with an instruction to use products registered by CIB&RC, follow the label and consult the local KVK.
  • Advice is shown only for confident predictions; for uncertain results the user sees candidate diseases with links.
  • A safety review replaced an older recommendation of streptocycline (an antibiotic the Government of India has moved to prohibit in agriculture) with a "do not use" warning.

Chapter 12Web Application

The website has seven pages: Landing, Diagnose, Results, Disease library, Model performance, Methodology and About. It is fully responsive and bilingual, supports drag-and-drop, file selection, browser camera capture and pasting an image (Ctrl/⌘+V or a Paste button), and accepts JPEG, PNG, WebP, AVIF, HEIC (iPhone), BMP, TIFF and GIF. Large photos are resized in the browser before upload.

Other features: downloadable HTML diagnosis report, print / save-as-PDF, dark mode, feedback (stored as unverified), uncertainty warnings, blurry-photo warnings.

  • Privacy: uploaded images are never stored — only a hash and prediction metadata.

Chapter 16Limitations and Future Scope

  • Field accuracy: 31.1%–26.5% on real field photos versus 99.6% on lab photos. Future: fine-tune on labelled field images (the PlantDoc domain-train split is already prepared) and collect Indian field data.
  • Closed set: only 38 classes; other crops, pests or nutrient problems are forced onto these labels.
  • Single architecture: ResNet-50 / Vision Transformer comparisons were planned but not trained, to keep the computational load suitable for a laptop; the training scripts support them.
  • Advisory review: content is source-cited but has not yet been reviewed by an agronomist; pesticide registrations change.
  • Calibration: one temperature cannot be right for both lab and field photos; confident field answers are still wrong about half the time.

Chapter 17Conclusion

KrishiGuard AI demonstrates a complete, working pipeline from verified public datasets to a deployed, bilingual web application. A transfer-learned EfficientNet-B0 reaches 99.56% accuracy and 99.49% macro-F1 on a leakage-free held-out test set, explains its decisions with heat-maps, and serves cited English and Hindi advice. Honest external testing shows that lab-trained models do not yet generalise to field photos; the application responds to this with calibrated confidence, explicit uncertainty states and by withholding advice when unsure.
